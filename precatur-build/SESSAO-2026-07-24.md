# Sessão Precatur × Twenty CRM — 2026-07-24

Registro completo do que foi conversado e feito nesta sessão. Fonte-de-verdade do modelo: `PRECATUR_MODEL.md` (raiz do repo).

## Objetivo
Rodar o Twenty CRM localmente e customizá-lo para a operação de **compra de precatórios** da Precatur: setores que se conversam (Comercial, Jurídico, Administrativo, Financeiro) + um **gerador de proposta** idêntico ao do app legado `~/Downloads/precatur`.

## O que foi feito (ordem)
1. **Clone + subida** do Twenty via Docker (imagens prontas `twentycrm/twenty:latest`) — server :3000, worker, Postgres 16, Redis. `.env` em `packages/twenty-docker/.env` com `ENCRYPTION_KEY`/`APP_SECRET` gerados. Sem usuário padrão → conta criada pela tela (B2C, sign-up por e-mail).
2. **Decisão de arquitetura**: "workspaces separados" no Twenty = tenants isolados (não conversam). Solução correta = **1 workspace**, objeto central **Precatório** + 1 objeto por setor ligado por **relação** (híbrido).
3. **Time Maestri** montado (roles no workspace "Twenty CRM"):
   - **Alicerce** — arquiteto/integrador (objeto central + relações + roles)
   - **Pregão** — Comercial (Negociação), **Toga** — Jurídico (Análise Jurídica), **Carimbo** — Administrativo (Processo Administrativo), **Cofre** — Financeiro (Pagamento)
   - **Pergaminho** — Dev Propostas (gerador)
4. **Modelo de dados criado via API de metadados** (`POST /metadata`, `createOneObject`/`createOneField`, Bearer = API key de Settings→APIs&Webhooks): 5 objetos + campos (incl. 11 campos extras sugeridos pelos setores) + relações + Kanban de Fase geral no Precatório + **4 roles** de permissão por setor (cada um edita só o próprio objeto; **ainda NÃO atribuídos a membros**).
5. **Gerador de Proposta portado 1:1** do `~/Downloads/precatur` (página React `proposta/page.tsx` + `window.print`, A4 paisagem, logo `precatur-logo-branco.png`). Preview standalone aprovado como fiel antes de integrar.
6. **Integração no fork** (branch `feat/precatur-gerador-proposta`): rota `/precatur/proposta` (fora do MainAppLayout, preview ao vivo + Gerar PDF, hidrata Negociação via `useFindOneRecord` + fallback mock) + ação fixada **"Gerar Proposta"** na Negociação (`GENERATE_PROPOSAL`) + workspace-command de upgrade que semeia a ação em workspace existente.
7. **Ambiente dev** (pra ver a feature): Node 24 (nvm) + Yarn 4 (corepack) + `yarn install`. Parados os containers Docker `server`/`worker`; `docker-compose.override.yml` expõe Postgres :5432 e Redis :6379 ao host; `packages/twenty-server/.env` e `twenty-front/.env` reusam `ENCRYPTION_KEY`/`APP_SECRET` do Docker → **mesmo banco, dados preservados**. Rodando: `twenty-server` :3000, `twenty-front` (Vite) :3001.
8. **Registro de exemplo** ponta-a-ponta (records via `/graphql`: `createPerson`/`createCompany`/`createPrecatorio`/`createNegociacao`): Cedente Maria Aparecida de Souza (PF), ente devedor União, Precatório 0012345-67.2023.4.03.0000 (TRF, alimentar, face R$250k / atualizado R$312,5k), Negociação `003cbc46-e7ff-4ff5-8825-7741672cbae8` (ofertado R$210k, deságio 32,8%). URL: `http://localhost:3001/precatur/proposta?negociacaoId=003cbc46-e7ff-4ff5-8825-7741672cbae8`.
9. **Correção B2C**: cedente é SEMPRE pessoa física (nunca empresa). Schema já estava certo (`negociacao.cedente→person`, `precatorio.cedente→person`); a única relação Company é `precatorio.enteDevedor` = governo devedor. Spec ajustado.
10. **Fix de scroll** na pré-visualização (só `PropostaDocumentStyles.ts`): `.proposta-page` on-screen ganhou `overflow-y:auto`+`min-height:0`; `@media print` reforçado com `overflow:visible!important` → PDF continua 3 páginas A4 paisagem.

## Como retomar o ambiente dev (do zero)
```bash
export NVM_DIR="$HOME/.nvm"; source "$NVM_DIR/nvm.sh"; nvm use 24; corepack enable
cd ~/twenty/packages/twenty-docker && docker compose up -d db redis   # sobe banco/redis (portas expostas via override)
cd ~/twenty && corepack yarn nx start twenty-server   # :3000
corepack yarn nx start twenty-front                   # :3001
```
Para voltar ao modo Docker puro: `docker compose up -d` (sobe server/worker de novo — mas aí a feature do fork não aparece, pois usa imagem pronta).
